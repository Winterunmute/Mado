# Mado V0.9 — Distribution & Release Preparation

## 1. Baseline and current status

- Verified the V0.8 baseline before V0.9 work: typecheck/build passed, 32/32 unit tests passed, Electron GUI stages passed, and production dependencies reported 0 audit vulnerabilities.
- Local Git history was already present. V0.7 baseline checkpoint is `6085c3d`; V0.8 and V0.9 work was developed on top of it.
- No working architecture was rewritten. Messenger, storage, adapters, filtering and the unified feed were preserved.
- V0.8 had one known limitation at handoff: screenshot inspection was unavailable; DOM/computed-style assertions were used instead. No critical functional defect was found.

## 2. Implemented release-preparation features

- **Windows NSIS installer configuration** in `package.json` for Mado 0.9.0 with per-user installation, Start Menu shortcut, optional desktop shortcut, configurable install directory, Mado icons and clear add/remove program metadata.
- **Local release script** `npm run dist:win` that builds the renderer/main processes and then packages the app.
- **First-run guide** with three concepts — Your Feed, Your Messenger, Your Rules. It is skippable, keyboard-focusable, does not request Facebook authentication, and is remembered via `onboardingComplete`.
- **Reopenable guide** from Settings.
- **Safe update check**: installed version shown in About; “Check for Updates” is implemented but reports that no official release source is configured. If `MADO_RELEASES_API` is set to a trusted GitHub Releases latest-endpoint at build/test time, it can report a newer version and open only the canonical release page. It never downloads or installs an installer.
- **Documentation**: README updates, `PRIVACY.md`, `THIRD_PARTY_NOTICES.md`, `CHANGELOG.md`, `RELEASE_CHECKLIST.md`, and this report.

## 5. Update strategy

- Default V0.9 builds have no release endpoint, so Update Check clearly reports `No official release source is configured for this build.` No URL is invented or silently contacted.
- `MADO_RELEASES_API` accepts only `https://api.github.com/repos/<owner>/<repo>/releases/latest` and derives a canonical `https://github.com/<owner>/<repo>/releases/latest` page. Other hosts are rejected.
- Update checks use a 10-second timeout, validate `tag_name`, compare numeric semver parts, and never auto-install.
- “Open release page” is allowed only for the derived canonical URL and uses the existing validated external-link handler.
- V1.0 plan: publish signed artifacts to GitHub Releases, configure the trusted endpoint, verify checksums and signature, then enable release-page prompts. Automatic installation remains out of scope until a signing and integrity strategy is finalized.

## 6. First-run experience

- Modal dialog with role `dialog`, `aria-modal`, labelled heading, focus moved inside on open, Tab cycling and Escape to skip.
- Three concise cards explain feed sources, existing Facebook login for Messenger, and user-controlled organization without an algorithm.
- Actions: **Skip for now** and **Add a source**; both mark onboarding complete, and the latter opens Sources.
- Onboarding state is stored in `settings.json` and can be reopened from Settings.
- Messenger authentication is never requested automatically.

## 7. Privacy, security and licensing review

- `PRIVACY.md` documents local storage paths, external connections, reader behavior, Messenger session isolation, notifications, backups, reset and uninstall retention. It avoids claiming that integrated platforms process no data.
- No analytics, advertising trackers or telemetry were added.
- Reconfirmed security boundaries in code: context isolation, sandboxing, no Node integration for remote pages, strict Messenger navigation policy, isolated `persist:messenger` partition, permission denial for web notifications, CSP, allowlisted/validated IPC, public-address validation for feeds/reader/discovery/OPML, bounded redirects and sanitized article HTML.
- `npm audit --omit=dev`: **0 production vulnerabilities**. Remaining dev/build advisories involve Vite/esbuild dev server and electron-builder packaging helpers; no forced or unrelated upgrades were applied.
- `THIRD_PARTY_NOTICES.md` records runtime/dev dependency licenses, Lucide and project icon attribution, and a clear statement that Mado is independent and unofficial.
- The historical README MIT statement is flagged as requiring explicit owner confirmation and a matching `LICENSE` file before public source publication. No license was chosen on the user's behalf.

## 12. Known issues and release blockers

- The installer is local-only and unsigned; SmartScreen warnings are expected until code signing is configured.
- No official update endpoint is configured by design.
- Real Messenger behavior under the current Facebook UI cannot be verified by the agent without an authenticated account.
- Live Reddit access from this environment has historically returned 404/429; treat as platform/network limitation.
- Vite/esbuild and electron-builder helper advisories remain development/build-time only.
- Public release requires: final license decision, code signing, clean-machine manual tests and explicit user authorization.
